PO Contract Validation Agent — EC2 Deployment Guide

Deploys the PO & Contract Match agent (Python / FastAPI + CrewAI backend, React frontend) to the same RPA server that already runs the AP Engine, using the same pattern: a GitHub Actions self-hosted runner, Nginx in front, an auto-starting NSSM Windows service, and a live RFC connection to SAP S/4HANA on 65.2.76.131 : 3357. Public URL: http://13.207.66.222:8091.

🐍 Python 3.12 + FastAPI + CrewAI ⚛ React (Vite) frontend 🏦 SAP RFC :3357 (reuses AP Engine's SDK) 🚀 GitHub Actions runner #4 🌐 Nginx → port 8091

Phase 1 — Server checks (once)

RDP into the RPA server

1

Check ports 8091 and 8210 are free

EC2 · PowerShell▼
netstat -ano | findstr ":8091 :8210"

Expected: no output. If a line shows LISTENING, pick another port and change it in both deploy\ec2\po-contract.conf (listen / proxy_pass) and .github\workflows\deploy.yml (PUBLIC_PORT / APP_PORT).

⚠Avoid port 2000 (Cisco SCCP — office firewalls drop web traffic on it; this is why the AP Engine moved to 8090).
2

Confirm the AP Engine setup is there to reuse (Python, SAP SDK, SAP port 3357)

EC2 · PowerShell▼
py -3.12 --version                                   # Python 3.12.x
[Environment]::GetEnvironmentVariable("SAPNWRFC_HOME","Machine")   # C:\sap\nwrfcsdk

The SAP connection on port 3357

Test-NetConnection 65.2.76.131 -Port 3357
# Must show:  TcpTestSucceeded : True

3357 is the RFC gateway of SAP instance 57 (33 + system number). The app does not take a port number: you enter system number 57 in Settings (Step 9) and the SAP SDK connects to 3357 itself. Since the AP Engine on this server already talks to SAP, this should already be True. If it is False, the SAP side's allow-list changed — the same request as in the AP Engine guide Step 5 applies (allow 13.207.66.222 on TCP 3357).

ℹIf any of the other lines fail, redo the matching step of the AP Engine guide (Step 3 Python, Step 4 SAP SDK). Nothing new needs installing for SAP.

The server .env — GitHub secret ENV_FILE (recommended) or a file

GitHub or EC2▼

5a — Generate the API key (shared secret for the frontend)

py -3.12 -c "import secrets; print(secrets.token_urlsafe(32))"

Keep this value — you'll paste it into the app's Settings in Step 9. Use a new value, not the one from your laptop.

5b — The .env content

# ── LLM — set exactly ONE (Mistral: mistral-large-latest) ──────
MISTRAL_API_KEY=<key>
# OPENROUTER_API_KEY=
# ANTHROPIC_API_KEY=
# GEMINI_API_KEY=

# ── API key the frontend must send (value from 5a) ─────────────
API_KEY=<value from 5a>

# ── SAP RFC SDK (shared with the AP Engine) ─────────────────────
SAPNWRFC_HOME=C:\sap\nwrfcsdk

# ── CrewAI: no tracing prompts / telemetry in a Windows service ─
CREWAI_TRACING_ENABLED=false
CREWAI_DISABLE_TELEMETRY=true
OTEL_SDK_DISABLED=true
ℹThe SAP host / system number / client / user / password are not read from .env by this app; they go into Settings in Step 9. The other keys in your laptop's .env (SAP_RFC_*, SAP_WEB_*, OUTLOOK_GRN_*) are not used by the current code — you can leave them out. The frontend and API are on the same origin (port 8091), so FRONTEND_ORIGIN is not needed.

5c — Put it in place (pick ONE)

OptionHow
A — GitHub secret (recommended, like AP_ENV_FILE)GitHub → poojashreeb-ship-it/EC2_PO_Contract_Match → Settings → Secrets and variables → Actions → New repository secret → Name ENV_FILE → paste the whole block from 5b (one setting per line) → Add secret. 10

End-to-end test

Browser + EC2▼

10a — SAP lookup only (fast, no LLM)

On the server, call the API's SAP lookup with a known PO number:

$key = "<API_KEY from Step 5a>"
Invoke-RestMethod http://127.0.0.1:8091/api/sap/po-record -Method Post -Headers @{ "X-API-Key" = $key } `
  -ContentType "application/json" -Body '{"po_number":"<a PO number in A4F>"}'

Expected: po_number, vendor_name, contract_price, payment_terms … from SAP. That proves the RFC path on port 3357 works end to end.

10b — Full validation

Upload a PO PDF and a contract PDF (e.g. input\sample_po.pdf / sample_contract.pdf from your laptop) → Validate. It can take a few minutes (two CrewAI crews + SAP). You get the SAP and contract validation results and a downloadable PDF report; a copy is kept in E:\POContract\app\output\.

Manual way — deploy by hand

For troubleshooting, or before the runner exists. The workflow does all of this automatically.

M

Clone, venv, test run, service, Nginx, firewall

EC2 · PowerShell (Admin)▼

M1 — Code + frontend build

git clone https://github.com/poojashreeb-ship-it/EC2_PO_Contract_Match.git E:\POContract\src
robocopy E:\POContract\src E:\POContract\app /E /XD .git
cd E:\POContract\app\frontend
npm ci
npm run build

Then create E:\POContract\app\.env (Step 5b).

M2 — Python environment + SAP check

cd E:\POContract\app
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt pyrfc==3.3.1
.\.venv\Scripts\python.exe -c "import pyrfc; print('pyrfc', pyrfc.__version__)"

"pyrfc 3.3.1 is yanked" is expected (same as the AP Engine).

M3 — Test run by hand

.\.venv\Scripts\python.exe -m uvicorn api.main:app --host 127.0.0.1 --port 8210

Browser on the server: http://127.0.0.1:8210/docs → the API page. Ctrl+C to stop.

M4 — Windows service

nssm install po-contract-api "E:\POContract\app\.venv\Scripts\python.exe" "-m uvicorn api.main:app --host 127.0.0.1 --port 8210"
nssm set po-contract-api AppDirectory "E:\POContract\app"
nssm set po-contract-api AppEnvironmentExtra "SAPNWRFC_HOME=C:\sap\nwrfcsdk" "PYTHONIOENCODING=utf-8" "PYTHONUTF8=1"
nssm set po-contract-api AppStdout "E:\POContract\logs\po-contract.out.log"
nssm set po-contract-api AppStderr "E:\POContract\logs\po-contract.err.log"
nssm set po-contract-api AppRotateFiles 1
nssm set po-contract-api AppRotateBytes 10485760
nssm set po-contract-api Start SERVICE_AUTO_START
nssm set po-contract-api DisplayName "PO Contract Agent (SAP PO validation)"
nssm start po-contract-api
nssm status po-contract-api

M5 — Nginx site + firewall

Copy-Item E:\POContract\app\deploy\ec2\po-contract.conf C:\nginx\nginx-1.30.0\conf\conf.d\po-contract.conf
cd C:\nginx\nginx-1.30.0
.\nginx.exe -t
.\nginx.exe -s reload          # if "Access is denied": nssm restart nginx
New-NetFirewallRule -DisplayName "PO Contract 8091" -Direction Inbound -Protocol TCP -LocalPort 8091 -Action Allow
Invoke-WebRequest http://localhost:8091/api/openapi.json -UseBasicParsing | Select-Object StatusCode   # 200
⚠Never edit nginx.conf itself — only the file in conf.d. nginx -t must say test is successful before reloading, otherwise the AP Engine and Avagama sites are at risk.
